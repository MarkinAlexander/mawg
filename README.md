# mawg - Multi-AWG Changer

Менеджер VPN-подключений для роутеров Keenetic/NetCraze (прошивка 5.1+,
Entware) и OpenWrt (24.10+). Один бинарник, веб-интерфейс и REST API
на порту 8090.

## Поддерживаемые протоколы

- **WireGuard** и **AmneziaWG** (1.x/2.x/3.x, включая I-пакеты-обфускацию) -
  нативными интерфейсами роутера: максимальная скорость, никакой лишней
  прослойки. Amnezia обменивает ключ `vpn://` на AWG-конфиги сама.
- **VLESS** (с TLS и REALITY, отпечаток uTLS), **VMess** (обе формы ссылки:
  контейнер v2rayN base64-JSON и legacy-cleartext; шифры канала sing-box -
  auto/none/zero/aes-128-cfb/aes-128-gcm/chacha20-poly1305), **Trojan** -
  исполняются движком sing-box в выделенном tun-интерфейсе. Транспорты:
  ws, grpc, xhttp, httpupgrade, http/h2.
- **Подписки**: вставьте ссылку или текст со списком узлов (vless://,
  vmess://, trojan://, wireguard://, amneziawg:// вперемешку) - mawg
  разоберёт всё разом и разложит по типам: WG/AWG станут нативными
  конфигами, прокси-узлы уедут в пул движка.

Прокси-узлам нужен движок sing-box (см. «Движок sing-box») - оригинальное
ядро, если уже стоит, или sing-box-lx одной кнопкой из панели.

## Быстрая установка

OpenWrt 24.10+ (`opkg`) и 25.x / snapshots (`apk`):

    curl -o /tmp/mawg.sh https://raw.githubusercontent.com/MarkinAlexander/mawg/main/install.sh && sh /tmp/mawg.sh

Keenetic/NetCraze (прошивка 5.1+ с Entware; сначала ставится curl, фирменный
wget не умеет https):

    opkg install curl && curl -o /tmp/mawg.sh https://raw.githubusercontent.com/MarkinAlexander/mawg/main/install.sh && sh /tmp/mawg.sh

Установщик сам определит платформу (OpenWrt или Keenetic) и архитектуру,
проверит WireGuard, предложит MagiTrickle, скачает бинарник из последнего
релиза и запустит сервис. Веб-интерфейс откроется на http://роутер:8090.
Флаги: -u (обновить), -r (удалить, --purge - с данными), --with-magitrickle /
--without-magitrickle (не спрашивать про MagiTrickle), --with-awg3 (поднять
AmneziaWG до 3.1 на OpenWrt).

Пакетный менеджер определяется автоматически: `opkg` на OpenWrt 24.10
и `apk` на OpenWrt 25.x. Поддержка Keenetic/Entware с `opkg` сохраняется.

## Удаление

Если проект не подошёл - одна команда останавливает mawg и снимает его
(данные настроек и пулов сохраняются):

    curl -o /tmp/mawg.sh https://raw.githubusercontent.com/MarkinAlexander/mawg/main/install.sh && sh /tmp/mawg.sh -r

Флаг `--purge` вместо `-r` удаляет и каталог данных (`/etc/mawg` на
OpenWrt, `/opt/etc/mawg` на Keenetic) - включая идентичности Amnezia
Free/Premium. MagiTrickle и ядро sing-box при этом не трогаются (они
ставятся пакетами - снимаются своим менеджером: `opkg remove magitrickle`
или `apk del magitrickle`). Группы MagiTrickle, созданные из mawg,
остаются в конфиге MT и продолжают работать с их текущими интерфейсами.

## Что умеет

- несколько именованных пулов-интерфейсов (proton, warp, ...) с фиксированными именами
- загрузка конфигов поштучно (.conf) и архивами (.zip), поддержка AWG 1.x/2.x/3.x
  включая I-пакеты (блобы)
- ротация конфигов внутри одного интерфейса: текущий не работает - применяется
  следующий; порядок конфигов задается стрелками в интерфейсе
- фоллбек на выбор: напрямую, держать последний конфиг или перевести группы на
  другой пул (перепривязка через MagiTrickle API, при восстановлении возврат)
- умный каскад пулов: при блокировке одного VPN (Proton, свой сервер) трафик
  к его эндпоинтам заворачивается через другой пул (например, WARP) с
  сохранением IP; гибкий триггер (после N отказов подряд или после перебора
  всех конфигов), возврат по расписанию/интервалу/кнопкой, антифлап -
  см. раздел «Умный каскад»
- наборы интерфейсов: группа MagiTrickle привязывается к списку интерфейсов
  (пулы + внешние), mawg держит ее на первом здоровом, при отказе переключает
  на следующий, при восстановлении возвращает
- реестр системных интерфейсов: пулы (управляются), внешние (только статус и
  привязка групп, конфиги не трогаются), скрытые (служебные не показываются)
- проверка состояния: handshake + проба через туннель (ping до публичного IP
  или HTTP-запрос вида http://www.gstatic.com/generate_204), RTT в статусе,
  свежий handshake засчитывается даже при потере icmp
- ручные включение/выключение пула, настройки пула и переименование (Keenetic)
  из веб-интерфейса
- панель Правила: полный CRUD групп и правил MagiTrickle из веб-панели -
  цвета групп, редактирование, drag-and-drop реордеринг, 10 шаблонов списков
  (Telegram, Meta, Discord, Twitter/X, TikTok, Roblox, Google, Porn, Anime,
  GeoBlock)
- панель Система: детект и установка зависимостей (WireGuard, AmneziaWG 3.1,
  MagiTrickle, компонент WireGuard на Keenetic) по подтверждению
- пулы из ссылок и подписок: vless://, vmess://, trojan://, wireguard://,
  amneziawg:// и Amnezia vpn:// - вставляются в «+ интерфейс» или подаются
  через CLI; транспорты ws/grpc/xhttp/httpupgrade, TLS и REALITY с
  uTLS-отпечатком
- движок sing-box для прокси-протоколов: vless/vmess/trojan работают в
  tun-интерфейсе движка, WireGuard/AmneziaWG - нативными интерфейсами;
  годится уже установленное оригинальное ядро или ядро sing-box-lx
  (см. ниже)
- режимы работы с подпиской: лучший пинг (автовыбор узла с минимальной
  задержкой), ручной выбор узла (селектор в настройках пула, применяется
  сразу и переживает обновление подписки), ротация по таймеру (строго на
  рабочие узлы); любой узел можно исключить тумблером - в конфиг движка
  он не попадает
- DNS: каскад серверов с автопереключением по содержимому ответа (канарейка
  спуфа), уровни L1-L5, шифрованные DoT/DoH-серверы, туннелирование DNS
  через пул - см. раздел «DNS» ниже
- зонный DNS: выбранные домены (зона = имя и все его поддомены) резолвятся
  назначенными серверами зоны через выбранный туннель; полный отвал -
  честная ошибка, имена не утекают в общий DNS
- автопроверка резервных DNS настраивается из панели: интервал, таймаут,
  циклы отключения/возврата, пауза возврата - баланс «быстрее заметить
  проблему» против «меньше грузить процессор» (слабым роутерам - реже)
- приватный режим (глаз в шапке): адреса серверов, ключи и ссылки в панели
  размываются - показывать по клику
- резервные копии: полный снимок настроек панели и MagiTrickle в один
  tar.gz, скачивание/восстановление из веб-интерфейса
- журнал событий с фильтрами, поиск по всем страницам настроек,
  подсказки [?] у каждого термина, мобильная версия с жестами
- авторизация панели (логин/пароль), ограничение доступа по IP/подсетям,
  смена порта и адреса прослушивания
- самообновление: `mawg update` или кнопкой в панели - качает свежий
  релиз с GitHub и переустанавливает бинарник
- логи только в RAM с ограничением 256 КБ, флеш не изнашивается

## Как устроена ротация

Каждый пул - это один интерфейс системы (слот Wireguard на Keenetic, интерфейс
с тем же именем на OpenWrt) и набор конфигов внутри. Движок раз в
checkIntervalSec проверяет активный конфиг (handshake + проба ping до probeHost
через туннель). После failThreshold отказов подряд конфиг уходит в cooldown на
cooldownMin минут и применяется следующий по списку. Список конфигов в
интерфейсе и есть приоритет: верхний применится первым, порядок меняется
стрелками вверх/вниз.

Когда пригодных конфигов не осталось, срабатывает фоллбек:

- direct (по умолчанию): интерфейс выключается, группы MagiTrickle на этом
  интерфейсе отключаются через API - трафик идет напрямую через провайдера;
  по истечении cooldown пул пробует восстановиться сам
- hold: последний конфиг держится, ротация приостановлена
- pool:имя: группы пула перепривязываются на интерфейс указанного пула и
  возвращаются обратно при восстановлении

Состояние (активный конфиг, счетчики, cooldown) хранится в state.json и
переживает перезагрузку роутера.

## Наборы интерфейсов

Набор - это упорядоченный список участников (пулы mawg и внешние интерфейсы) и
привязанные к нему группы MagiTrickle. mawg каждые 30 секунд выбирает первого
здорового участника (пул в состоянии up, внешний интерфейс с link up и свежим
handshake) и держит на нем все группы набора. При отказе текущего участника
группы переключаются на следующего, при восстановлении возвращаются на
приоритетного. Группы в наборе не отключаются при фоллбеке пула-участника -
ими управляет набор.

## Пробы

Проба настраивается для пулов (шестерёнка в карточке) и для внешних
интерфейсов (шестерёнка в панели интерфейсов), включая сторонние туннели
tun/tap - отметите интерфейс внешним и настройте пробу: тип HTTP-страница 204 (по
умолчанию http://www.gstatic.com/generate_204) или ping публичного IP.
HTTP-запрос идет через туннель с привязкой к интерфейсу, ответ любого кода =
успех. В статусе показывается RTT.

Для каждой пробы можно задать порог RTT с галочкой: если пинг выше порога
(например 700 мс), интерфейс считается деградировавшим - для пула это
запускает ротацию, для внешнего интерфейса - исключает его из наборов.

Свежий handshake (до 2 минут) перекрывает потерю icmp - туннель считается
рабочим. Порог RTT перекрытием не пользуется: деградация видна честно.

## Проверка канала провайдера

В панели Система настраивается проба основного канала интернета (по умолчанию
выключена, можно указать любую цель, например http://ya.ru/). Перед тем как
засчитать отказ интерфейса, mawg проверяет канал той же пробой: канал
недоступен или выше порога - отказ интерфейса не засчитывается и ротация не
запускается (бессмысленно менять конфиги, когда лежит сам интернет).
Результат виден в статусе: "...канал провайдера недоступен, отказ не
засчитан".

## Установка на OpenWrt

Требуется OpenWrt 24.10+ (протокол amneziawg доступен из коробки в виде пакетов).

1. Скопируйте бинарник на роутер (архитектуру смотрите в `uname -m`,
   `apk --print-arch` на OpenWrt 25.x или `opkg print-architecture` на 24.10):

       scp dist/mawg-386 root@роутер:/usr/bin/mawg
       ssh root@роутер chmod +x /usr/bin/mawg

2. Создайте службу (файл deploy/openwrt-init.sh):

       scp deploy/openwrt-init.sh root@роутер:/etc/init.d/mawg
       ssh root@роутер "chmod +x /etc/init.d/mawg && /etc/init.d/mawg enable && /etc/init.d/mawg start"

3. Откройте http://роутер:8090

Пути: бинарник /usr/bin/mawg, данные /etc/mawg, лог /var/log/mawg.log (tmpfs).

Для AWG 2.x/3.x серверов (I-пакеты) нужны пакеты amneziawg из репозитория
amnezia-vpn/amneziawg-openwrt - панель Система покажет версию и предложит
обновление. Стоковые пакеты 24.10 умеют только AWG 1.x: простые конфиги
(Cloudflare WARP) работают, серверы с обязательной обфускацией (Proton и
похожие) - нет.

## Установка на Keenetic/NetCraze

Требуется прошивка Keenetic OS или NetCraze 5.1+, компонент WireGuard (Web UI - Обновления - Компоненты)
и Entware на USB.

1. Скопируйте бинарник и init-скрипт (mips: mawg-mipsle, arm: arm64-сборка):

       scp -P 222 dist/mawg-mipsle root@роутер:/opt/bin/mawg
       scp -P 222 deploy/keenetic-init.sh root@роутер:/opt/etc/init.d/S99mawg
       ssh -p 222 root@роутер "chmod +x /opt/bin/mawg /opt/etc/init.d/S99mawg && /opt/etc/init.d/S99mawg start"

2. Откройте http://роутер:8090

Пути: бинарник /opt/bin/mawg, данные /opt/etc/mawg, лог /tmp/mawg.log (RAM).
Пул привязывается к слоту Wireguard (Wireguard0, Wireguard1, ...): mawg
настраивает слот через ndm, включая I-пакеты AWG 2.0 (asc), и сохраняет
конфигурацию - все переживает перезагрузку роутера, включая автозапуск из
Entware. Старого лимита в 10 слотов на свежих прошивках нет; если свободных
слотов нет, новый создается кнопкой "+ слот" прямо в диалоге создания пула.
На Keenetic OS 5.2+ локальный API требует токен (создается в веб-интерфейсе
Keenetic) - укажите его в панели "Система", без токена mawg работает через
CLI медленнее.

## Первый запуск

1. Нажмите "+ интерфейс", укажите имя пула (латиница, например proton) и слот
   (Keenetic; нет свободного - "+ слот" создаст новый) или протокол (OpenWrt)
2. Раскройте "Конфиги" и перетащите туда .conf-файлы или .zip-архив - конфиг
   применится сразу, пул начнет проверяться
3. Настройте пул по шестерёнке: проба, интервалы, фоллбек, переименование
   (Keenetic)
4. Для маршрутизации по доменам установите MagiTrickle и создайте группы в
   панели Правила, привязав их к интерфейсу пула
5. Системные интерфейсы, которые mawg не управляет, но нужны для привязки
   групп или наборов, отметьте как внешние в панели "Интерфейсы роутера"

## Пулы из ссылки или подписки

В «+ интерфейс» есть режим ссылки: вставьте vless://, vmess://, trojan://,
wireguard://, amneziawg://, Amnezia vpn:// или ссылку/текст подписки с
несколькими узлами - mawg разберёт, покажет план (нативные конфиги, узлы для
движка, дубликаты, пропуски с причинами) и создаст пул. Поддерживаются
транспорты ws, grpc, xhttp, httpupgrade, http/h2; TLS и REALITY, включая
uTLS-отпечаток (fingerprint). vmess понимается в обеих формах - контейнер
v2rayN (base64 JSON) и legacy-cleartext; шифры канала - набор sing-box
(auto/none/zero/aes-128-cfb/aes-128-gcm/chacha20-poly1305), неизвестный
шифр уводится на auto.

Узлы WireGuard/AmneziaWG становятся обычными конфигами пула (нативный
интерфейс), прокси-узлы (vless/vmess/trojan) живут в tun-интерфейсе
движка sing-box - им нужен установленный sing-box (см. «Движок sing-box»
ниже). Ссылка Amnezia vpn:// обменивается на AWG-конфиги у gateway (см.
Amnezia Free/Premium ниже).

Те же разбор и создание доступны по REST (`POST /api/v1/links/inspect`,
`POST /api/v1/pools/from-source`) и из консоли:

    mawg links parse "vless://..."   # разобрать ссылку/.conf/подписку в JSON
    mawg links fetch <url>           # скачать подписку: заголовки + модель узлов
    mawg links amnezia "vpn://..."   # обменять ключ Amnezia на AWG-узлы
                                     # (опционально -via socks5://...)

## Установка MagiTrickle из панели

Если MagiTrickle не установлен (или стоит апстримный бинарь без ревизии
форка), mawg ставит его сам: в «Системе» у пункта MagiTrickle кнопка
установки/обновления. mawg определяет платформу и архитектуру (opkg
print-architecture / apk), скачивает пакет mawg-форка
(`magitrickle_<ver>_<платформа>_<таргет>.ipk`/`.apk`) из релиза
[MarkinAlexander/magitrickle](https://github.com/MarkinAlexander/magitrickle/releases)
и ставит штатным менеджером пакетов с зависимостями (opkg install /
apk add), затем включает и запускает службу. Форк нужен для источников
групп (sources), OUTPUT-jump роутера и API каскада DNS - ревизия видна в
версии бинаря (`0.8.2-rev10-mawg-dev`); версия без `rev` = апстрим, панель
предложит обновление. Пакет обновляется той же кнопкой при выходе нового
релиза форка.

## DNS: перехват, каскад, защита от подмены

Для маршрутизации по доменам MagiTrickle перехватывает DNS локальной сети
(dnsmasq роутера направляется на MT). mawg управляет тем, КУДА MagiTrickle
дальше несёт запросы, и следит, чтобы ответы не подменялись:

- **Цепочка серверов (L1-L5)**: основные → основные через туннель →
  запасные → Яндекс → провайдер. Переключение автоматическое: сервер не
  отвечает или врёт - запросы уходят на следующий, «оживет» - роутер
  вернётся к нему сам.
- **Канарейка спуфа**: здоровье сервера проверяется не фактом ответа, а
  содержанием - контрольный запрос к deb.torproject.org сверяется с
  эталонным набором адресов. «Живой» сервер, отдающий подмену (яд),
  признаётся мёртвым - обычный пинг такого не ловит.
- **Шифрованные серверы**: уровни могут быть DoT (`tls://1.1.1.1`) и DoH
  (`https://dns.google`) - ответы по пути не подменить и не подсмотреть.
  Готовые кнопки: Google, Cloudflare, AdGuard.
- **DNS через туннель**: уровень L2 направляет запросы к публичным
  резолверам внутри выбранного VPN-пула (в туннель попадают и адреса
  DoT/DoH-серверов) - заблокировать DNS снаружи становится нельзя.
- **Проверка**: кнопка «Проверить все уровни» прогоняет канарейку через
  каждый сервер своим транспортом и показывает вердикт и задержку;
  карточка «Проверка DNS и сети» на Обзоре - матрицей по всем путям
  (UDP/DoT/DoH, «интернет жив?» мимо DNS), со своим списком серверов
  (до 16 своих уровней - DNS → «Резервные серверы» → подсказка [?]) и
  выбором пути пробы (всё / напрямую / через MT). Вердикты честные:
  «подмена» (сервер отвечает фальшивыми адресами) - отдельно от «нет
  ответа».

DNS-возможности живут в mawg-форке MagiTrickle: каскад - rev8+, DoT/DoH -
rev11+, зоны - rev13+, автопроверка из панели - rev14+ (ставится и
обновляется кнопкой в «Системе» - см. «Установка MagiTrickle из панели»).

### Автопроверка резервных серверов: как часто и насколько строго

Цепочка серверов жива потому, что MagiTrickle регулярно проверяет каждый
своим контрольным запросом. Частота и строгость - ваш выбор (DNS →
«Резервные серверы» → «Автопроверка серверов»): у каждого поля
подсказка [?] с минусами в обе стороны.

- **интервал** (5-300 сек) - как часто проверять. Чаще - быстрее
  замечаем смерть сервера, но каждое срабатывание даёт всплеск нагрузки
  на процессор: проверка шифрованного сервера - это свежее
  TLS-рукопожатие. Реже - процессор свободнее, но проблема видна
  за интервал × циклы.
- **таймаут** (1-10 сек) - сколько ждать ответа. Меньше - быстрее
  вердикт, но медленный сервер ложно пометится нерабочим (ложные
  переключения). Больше - надёжный вердикт, но каждая проверка дольше
  занимает процессор.
- **циклов до отключения** (1-20) - сколько провальных проверок подряд
  считается смертью сервера. Меньше - быстрая реакция, но флап на одной
  потере; больше - стабильно, но реально мёртвый сервер работает
  лишние циклы, пока его заметят.
- **циклов до возврата** (1-20) и **пауза возврата** (0-3600 сек) -
  защита от дёрганья: снова живой сервер возвращается только после
  N удачных проверок и не чаще паузы. Меньше - быстрый возврат, но
  флапающий сервер будет дёргать маршруты; больше - стабильно, но
  резерв надолго остаётся главным.

Автопроверку можно выключить совсем (тумблер): процессор свободнее, но
упавший сервер никто не заметит - запросы продолжат уходить в мёртвый.
Проверки стартуют по очереди с паузами, чтобы на слабых роутерах не
складывались в залпы; настройка пишется в конфиг MT и переживает
перезагрузку.

### Зонный DNS: выбранные домены - через свой туннель

Зона - это имя домена и все его поддомены: corp.example.com покрывает и
portal.corp.example.com, и любой уровень глубже. Что попало в зону -
идёт к НАЗНАЧЕННЫМ серверам зоны, а не в общий список: рабочие домены
резолвятся через корпоративный DNS, доступный только внутри рабочего
VPN; домашние сервисы - через собственный туннель; чувствительные
списки - через отдельный чистый резолвер.

Заводится в DNS → «Зонные DNS» → «+ зона»: имя зоны, её серверы (по
одному на строку, порядок = приоритет) и путь к ним:

- **напрямую** - серверы зоны должны быть доступны с роутера как есть;
- **через пул** - адреса серверов заворачиваются в туннель выбранного
  пула (mawg сам держит служебную группу dnszone-*): пул лежит -
  серверы зоны недостижимы;
- **через готовый интерфейс** - вручную настроенный WG-туннель и
  подобное (список тот же, что в выборе группы у правил).

Запрос сверяется с самыми длинными зонами первыми: lab.corp.example.com
побьёт corp.example.com, и только потом общий список.

Отвал - по вашему выбору. По умолчанию **fail-closed**: ни один сервер
зоны не ответил - клиент получает честную ошибку, а имена зоны НЕ
утекают в общий DNS (переключатель «При полном отвале - общий DNS
(fallback)» - осознанное исключение). На строке зоны: чекер
включения/выключения, карандаш правки, корзина удаления и кнопка-стрелка
«проверить зону» - контрольный запрос через каждый сервер по пути
клиентов, два прогона (первый греет туннель); вердикты по каждому
серверу - рядом.

На Keenetic собственные серверы DNS роутера (DoH/DoT, настроенные в вебе
Keenetic) mawg не меняет - только показывает с проверкой каждого.
Переключение dnsmasq OpenWrt на MT и обратно - кнопкой в DNS-разделе,
с бэкапом настройки.

## Движок sing-box

Прокси-протоколы (vless, trojan) исполняются движком sing-box: mawg собирает
конфиг с tun-интерфейсом и наружными узлами, привязывает пул к tun-имени.
Годится уже установленное оригинальное ядро (из пакетов Entware/OpenWrt или
стоящее от других панелей) - mawg детектит его по `sing-box version` и не
трогает.

Для прокси-протоколов используется ядро sing-box-lx (lx-профиль sing-box).
Сейчас это наш форк lx-ядра - временная мера: нам нужны upx-сборки под все
платформы. Неупакованное lx-ядро занимает 60-90 МБ, упакованное - 15-30 МБ,
и на роутере эта разница обычно и решает, влезает ядро в корень или нет.
upx-профиль принят в апстрим нашим PR - когда такие сборки появятся в
релизах оригинального автора, форк будет заменён на оригинал. Ставится из
панели (Система → «ядро sing-box-lx»); посмотреть, какие релизы есть под
вашу архитектуру и в каких профилях, можно командой `mawg singbox discover`.
После установки lx-ядра пулы с движком пересобираются под него автоматически.

Про профиль upx: экономия десятков мегабайт свободного места (15-30 МБ
против 60-90 МБ у неупакованного), но при каждом запуске распаковывается
в память - старт чуть дольше, и процесс держит в RAM больше, чем unpacked;
служебные утилиты по упакованному файлу не работают (например,
`go version -m`). Рекомендация: на роутерах с малым флешем - upx; если
флеша много, а памяти впритык - plain.

## Порт и адрес панели

Веб-панель слушает 0.0.0.0:8090. Если 8090 уже занят другим сервисом,
демон не поднимется и напишет это в лог с подсказкой. Варианты:

    mawg port 9090 && mawg restart           # сменить порт насовсем (1-65535)
    mawg listen 192.168.1.1 && mawg restart  # сменить адрес прослушивания
    mawg -port 9090                          # разово запустить на другом порту

Порты 8080 (веб/API MagiTrickle) и 3553 (его dns-proxy) панели не отдаются -
отказ без подтверждений. `mawg port` перед записью пробует занять указанный
порт: если он занят прямо сейчас - предупредит и попросит подтверждение (в
скриптах без терминала откажет). Установщик понимает `sh install.sh --port
9090` и на свежей установке сам заметит занятый 8090 и предложит ввести
другой порт. Текущие настройки: `mawg settings`; сброс всего доступа к
дефолту: `mawg reset access`.

## Командная строка (CLI)

    mawg                    запустить демона (обычно это делает init-скрипт)
    mawg status             состояние демона и пулов
    mawg start|stop|restart управление сервисом (init-скрипт платформы)
    mawg update             проверить и установить обновление с GitHub
    mawg settings           настройки панели (авторизация, порт, адрес, доступ)
    mawg port <1-65535>     сменить порт веб-панели
    mawg listen <ip>        сменить адрес прослушивания (0.0.0.0 | 127.0.0.1 | IP)
    mawg reset access       сбросить доступ: порт 8090, адрес 0.0.0.0, allowlist очищен
    mawg auth off|on        выключить/включить авторизацию панели (off - НЕБЕЗОПАСНО)
    mawg allow <ip|cidr>    добавить адрес в список разрешённых к панели
    mawg allow list|clear   показать/очистить разрешённые адреса
    mawg links parse <x>    разобрать ссылку/.conf/подписку в модель узлов (JSON)
    mawg links fetch <url>  скачать подписку: заголовки + модель узлов
    mawg links amnezia <vpn://> [-via socks5://...]  обменять ключ Amnezia
    mawg singbox discover   релизы ядра sing-box-lx: матрица arch x flavor
    mawg -reset-auth        задать новый пароль панели интерактивно
    mawg -password <pass>   задать пароль без вопросов

Флаги демона: `-platform openwrt|keenetic`, `-base <dir>` (каталог данных),
`-port <n>` и `-listen <ip>` (перекрывают настройки на этот запуск),
`-no-auth` (разово без авторизации, аварийный). Смена порта, адреса,
allowlist и авторизации вступает в силу после `mawg restart`; то же
настраивается в веб-панели (Настройки).

## Amnezia Free без аккаунта

В «+ интерфейс» выберите «Amnezia Free без аккаунта», задайте имя и создайте
пул. mawg запрашивает официальный каталог `v1/services` без ключа и аккаунта.
Только если Free доступен и предлагает AWG, выполняется accountless
`v1/config` с регионом из каталога и локальным публичным ключом.
Premium-подписка и её слоты не используются. Регион нельзя подменить в UI/API.
Работает на OpenWrt и на Keenetic (нужна прошивка 5.1+ с поддержкой AWG 2.0 -
конфиг Free применяется в слот Wireguard как любой AWG-конфиг; на более
старой прошивке пул поднимется, но хендшейка не будет).

Пул создаётся выключенным: проверьте настройки и включите его обычной кнопкой.
`POST /api/v1/pools/amnezia-free` принимает `name`, необязательные `fallback`
и `probeHost`; действует общая авторизация/allowlist и лимит тела 4 КиБ.
Повтор для существующего Free-пула не выдаёт новый конфиг; второй Free-пул
отклоняется. Удаление пула не удаляет сохранённую Free-идентичность.

Отдельный `free.json` (`0600`) хранит UUID, приватный ключ, полученные credentials
и конфиг. После ошибки UUID/ключ сохраняются; успешная выдача сохраняется до
создания пула, поэтому перезапуск/повтор после локальной ошибки не перевыпускает
её. Секреты не возвращаются в status/settings/events. Существующие конфиги не
перезаписываются, неизвестные AWG-параметры отклоняются без удаления полей.

Ограничения: поддерживается первичное получение Free AWG, без автоматического
обновления истекающих конфигов и решения CAPTCHA. Недоступный регион, иной
протокол или CAPTCHA дают явную ошибку без пустого пула; для CAPTCHA используйте
официальный клиент и существующий ручной импорт. Ответ API не доказывает
работоспособность VPN-туннеля. Доступность сервиса зависит от региона
и ответа официального gateway.

## Amnezia Premium: один слот, смена страны

Создайте пустой пул с протоколом `amneziawg` на OpenWrt (на Keenetic выберите
слот WireGuard). В карточке импортируйте Premium `vpn://` ключ, затем выберите
страну и нажмите «Сменить страну». Повторный импорт при смене страны не нужен.
Поддерживается одна Premium-подписка и один связанный с ней пул на роутере.
Старый статический обмен Premium AWG через `links amnezia`, «из источника»
и «обновить источник» отклоняется до запроса к провайдеру: используйте
Premium-панель, чтобы не создавать отдельную идентичность устройства.
Обмен Free AWG и Premium VLESS остаётся прежним. Premium API защищён
общей авторизацией/allowlist панели (если авторизация явно не отключена).

mawg использует app-режим `v1/config`: UUID устройства сохраняется при
перезапуске и смене страны, а текущий конфиг заменяется, не накапливается в
пуле. Статические `native_config` экспорты не создаются. Доступные страны
берутся из подписки, регистрация UUID и страны проверяется через
`account_info`. Автоматического перебора стран нет; пробы и фоллбек пула
работают как раньше. Для расширенных AWG-параметров нужны совместимые
прошивка/пакеты; неизвестные поля и некорректные диапазоны H отклоняются,
а не удаляются из конфига.

Ключ подписки и UUID находятся в `premium.json` в каталоге данных mawg с
правами `0600`, а не в ответах status/settings. Удаление пула не удаляет эту
идентичность и не отзывает устройство у провайдера: повторный импорт того же
ключа в новый пустой пул использует прежний UUID. Полное удаление каталога
данных уничтожит идентичность; сохраните его при переустановке. Не открывайте
веб-порт в интернет и вводите ключ только из доверенной локальной сети.

Для переноса уже зарегистрированного устройства до первого импорта создайте
в каталоге данных `premium.json` с `{"installationUUID":"UUID существующего устройства"}`
и правами `0600`. Выполните это при остановленном mawg: UUID загружается при
старте. Импорт сохранит этот UUID вместо выделения нового. Не копируйте UUID
другого продолжающего работать устройства: смена страны заменит его регистрацию.

При ошибке получения или применения сохраняется предыдущий локальный
конфиг. Но сервер мог уже сменить регистрацию: старый файл не гарантирует
работающий старый туннель. Интерфейс показывает незавершённую смену;
повторите выбор страны. Подготовленный приватный ключ сохраняется до запроса
и используется при повторе после таймаута. Успешный API-ответ не гарантирует
мгновенную готовность туннеля или точную геолокацию выходного IP.

## Генератор WARP

На «Интерфейсах» есть карточка «Генератор WARP»: панель регистрирует
устройства Cloudflare WARP прямо с роутера и собирает пул с готовыми
конфигами. Ключи X25519 генерируются локально - в Cloudflare уходит только
публичный ключ; сторонние воркеры-генераторы не используются (у них
приватный ключ транзитом через чужой сервер).

Параметры: количество конфигов (1-16, каждое - отдельная регистрация),
эндпоинты (режим «Случайно» - у каждого конфига своя пара адрес:порт из
сетей Cloudflare WARP; «из проверенного списка»; или свой host:порт) и
разрешённые подсети (AllowedIPs): пресеты сервисов (YouTube, Telegram,
Discord и др.) и свои подсети - строго IP или CIDR, домены сознательно не
принимаются (WireGuard в AllowedIPs понимает только подсети, а резолв
домена - неполный снапшот). Без выбора - полный туннель. Конфиги
простые WireGuard: без DNS, MTU 1280, keepalive 25.

Каждый конфиг сразу проверяется живой пробой (handshake/пинг), вердикты
видны в диалоге; активным остаётся первый рабочий. Списки подсетей
и подход генерации - открытый проект warp-generator
(https://warp-generation.github.io/), там же можно сгенерировать конфиг
вручную; контракт регистрации и перебор хостов API - по LxBox. Результат
диалога позволяет скачать конфиг файлом: обычный WG или вариант с полями
обфускации AmneziaWG 2.0 для внешних AWG-клиентов (Windows и др.;
нативные интерфейсы Кинетиков этот вариант не поднимают).

В карточке существующего WARP-пула (созданного генератором или собранного
из своих конфигов - пул узнаётся по адресам Cloudflare) есть кнопка
«Генерация нового конфига»: ещё одна регистрация с теми же разрешёнными
подсетями и новым адресом:портом, без мастера.

`api.devices.cloudflare.com` (основной хост API) и
`api.cloudflareclient.com` (запасной) часто недоступны из РФ без анти-DPI:
если оба молчат, панель показывает честную ошибку с рекомендацией zator
(https://github.com/AloofLibra/zator - обвязка zapret2 для роутеров) и
ссылкой на сайт-генератор. Регистрации идут последовательно; Cloudflare
может рейт-лимитить (один автоматический ретрай). Идентичность устройств
(id/токен, без приватных ключей) хранится в `warp.json` (0600); приватные
ключи живут только в конфигах пулов.

REST API: `GET /api/v1/warp/presets` - пресеты и лимиты;
`POST /api/v1/warp/generate` - `{count, mode: random|fixed, endpoint,
sites, domains}` - создать пул; `POST /api/v1/pools/{name}/warp` - +1
конфиг в варп-пул; `GET /api/v1/pools/{name}/configs/{file}?variant=awg`
- конфиг с полями обфускации.

## Умный каскад: один VPN через другой

Живой кейс: провайдер начинает душить один конкретный VPN - Proton
целиком или ваш собственный сервер, - а интернет при этом работает.
Ротация честно перебирает конфиги, но если перекрыты сами адреса
серверов, лягут все. Умный каскад решает это без смены VPN: трафик к
эндпоинтам пула A заворачивается через другой пул B (например, WARP) -
вы продолжаете получать IP Proton, но путь к серверам Proton идёт
через WARP. Это не фоллбэк: фоллбэк переносит группы на другой пул, и
внешний IP меняется; каскад IP сохраняет.

Настраивается в диалоге пула A: упорядоченный список запасных путей Via
(порядок стрелками = приоритет, включается первый живой), когда включать
каскад и как возвращаться на прямой путь. Чип «умный каскад» на карточке
пула и в строке интерфейса показывает состояние без захода в настройки:
спокойный - настроен и ждёт, бирюзовый активный - «через warp
(каскад)». Клик по чипу открывает карточку с полным планом (пути,
триггер, возврат, текущее состояние), все переключения - в журнале
событий.

Режимы включения:

- «после отказов подряд» (быстрый) - активный конфиг проверили напрямую
  N раз (по умолчанию 3), фейл - включается Via и этот же конфиг сразу
  проверяется уже через него (две пробы с паузой на handshake). Ожил -
  конфиг остаётся активным, ротация не нужна, IP сохранён. Не ожил -
  конфиг проверен обоими путями, берётся следующий напрямую, с ним то
  же самое, и так по кругу;
- «после перебора всех конфигов пула» - штатная ротация честно
  перебирает всю подписку, и только когда все конфигы лежат в кулдауне,
  каскад включается перед фоллбэком. На большой подписке (60 конфигов
  с кулдауном) это часы - там нужен первый режим.

Страховки. Перед включением проверяется сам Via: лежит и он - каскад не
включается, работает обычный фоллбэк (заворачивать в мёртвое
бессмысленно). После включения mawg сам дважды проверяет туннель A уже
через Via - не ожил, каскад тут же снимается, честный фоллбэк. Если при
живом каскаде A умер и через Via, автомат пробует следующий путь из
списка, а когда список кончился - фоллбэк. Умер канал провайдера
(WAN-проба) - отказы не засчитываются, каскад ложно не включается.

Возврат на прямой путь: по расписанию (например, в 03:00), по
интервалу (раз в N часов) или только кнопкой «Проверить прямой
сейчас» в карточке пула - она минует антифлап. В момент проверки
правило каскада снимается на короткое окно, проба идёт напрямую: ожил
- каскад снят, нет - вернулся. Антифлап (по умолчанию 10 минут)
не даёт дёргаться на флапах.

Пример. Пул proton (подписка на 60 конфигов) блокируют: в настройках
пула включаем умный каскад через пул warp, режим «после 3 отказов»,
возврат по расписанию в 03:00. Провайдер перекрывает адреса Proton -
через минуту-две панель включает каскад (в журнале: «каскад включён:
прямой доступ потерян, путь через warp»), клиенты продолжают работать
с прежним IP. Ночью проба напрямую оживает - каскад снимается сам.

## Интерфейсы роутера

Панель показывает все WireGuard-интерфейсы системы с их режимом:

- пул - управляется mawg (ротация, фоллбек)
- внешний - mawg не трогает конфиг, но показывает статус (link, handshake)
  и разрешает привязывать группы MagiTrickle и включать в наборы
- скрытый - служебный интерфейс, не показывается больше нигде

Кнопка "показать скрытые" раскрывает служебные, режим меняется кнопкой в
строке. По умолчанию все неуправляемые интерфейсы скрыты.

## Панель Правила (MagiTrickle)

MagiTrickle должен быть установлен и запущен на порту 8080 (проверяется
автоматически, состояние видно в шапке). Возможности:

- создание групп с цветом, привязка к интерфейсу пула (подпись - имя пула или
  описание слота Keenetic)
- правила пяти типов: домен, домен+поддомены, подсеть, маска, регулярное
  выражение (подсказки по каждому типу - в форме ввода)
- редактирование групп (имя, цвет, интерфейс) и правил по кнопке с карандашом
- drag-and-drop реордеринг групп и правил за ручку слева (порядок сохраняется
  в конфиг MagiTrickle)
- включение/выключение групп и правил тумблерами
- шаблоны списков одним нажатием: Telegram, Meta (Instagram/Facebook/WhatsApp),
  Discord, Twitter/X, TikTok, Roblox, Google (AI/Meet/Play), Porn, Anime,
  GeoBlock (доступ из РФ через VPN: ChatGPT, Claude, новости и др.) -
  домены, подсети IPv4 и IPv6
- импорт групп и правил текстом: вставьте список - mawg разберёт,
  покажет дубликаты до применения
- чекеры «Скрывать выключенные группы» / «Скрывать выключенные правила»
  со счётчиками: можно спрятать неактивные группы, оставив правила
  видимыми для включения
- источники списков указываются честно: в панели и в API у каждого шаблона
  стоит ссылка на репозиторий
  [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains) и
  версия списков (дата, коммит). Списки запечены в бинарник, обновление -
  `sh deploy/update-presets.sh` (скачивает свежие версии и фиксирует их
  происхождение в MANIFEST.json)

Интеграция с фоллбеком: когда пул уходит в direct-фоллбек, его группы
отключаются, при восстановлении - включаются обратно. Ручное выключение пула
делает то же самое.

## Сборка из исходников

Требуется Go 1.26+. Для сжатия бинарников положите UPX в tools/
(https://github.com/upx/upx/releases, распаковать в tools/upx-*/):

    sh deploy/build.sh          # оба роутера, с upx около 2 МБ
    sh deploy/build.sh mipsle   # только keenetic (mips)
    sh deploy/build.sh 386      # только openwrt x86

Архитектуры: Keenetic mips -> mipsle; Keenetic arm -> arm64; OpenWrt x86 -> 386/amd64.
Для другой архитектуры: CGO_ENABLED=0 GOOS=linux GOARCH=<arch> go build ...

Перед коммитом: go vet ./... && go test ./...

## Известные особенности

- probe-цель обязана быть публичным IPv4-адресом или http(s)-ссылкой
  (валидатор не пустит приватный IP - иначе можно закрыть себе LAN)
- на OpenWrt два пула не могут иметь одинаковый probe-хост при ICMP-пробе
  (конфликт host-маршрутов в main-таблице): используйте разные адреса, например
  1.1.1.1 и 8.8.8.8, или http-пробы. На Keenetic такого конфликта нет
- переименование пула доступно только на Keenetic: на OpenWrt имя пула - это
  имя системного uci-интерфейса
- фоллбек pool:X не допускает циклов (A на B, B на A) - валидатор отклонит
- утилита управления на OpenWrt может называться awg или amneziawg -
  определяется автоматически
- MagiTrickle API не принимает пустые id/color в PUT/POST - mawg заполняет их
  за вас
- веб-интерфейс обновляет данные каждые 5 секунд, открытые раскрывающиеся
  списки и скролл журнала сохраняют состояние

## Привязка MagiTrickle

На Keenetic пул занимает свободный слот Wireguard (при создании пула в списке
слоты размечены: занятые системой помечены, слоты других пулов mawg скрыты,
свободный выбирается автоматически) - имя интерфейса получается из слота
(Wireguard4 -> nwg4), и группа MagiTrickle привязывается к nwg4. На OpenWrt
имя интерфейса = имя пула (proton, warp). Группы из наборов интерфейсов можно
привязывать и к сторонним туннелям (tun0 и подобные) - отметите их внешними
в панели интерфейсов. Проверить привязку можно тестовым правилом namespace
whatismyipaddress.com - сайт покажет IP туннеля.
